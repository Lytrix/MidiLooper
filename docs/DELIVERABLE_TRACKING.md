## Workflow update — 2026-10-12 (uploaded to the test device; no Git delivery)

**One owner per persisted Set index path (bugfix, `DEC-120`).** The Set browser showed **no Sets at all**
because `/MidiLooper/sets/index.bin` was written by two owners in two layouts — the catalog's 16-byte index
and the legacy SavedSet sequence index's 8 bytes — and the boot reconcile rewrote it in the legacy layout on
every boot, destroying the catalog index; `listSetRevisionBrowserEntries` then failed its 16-byte read and a
commit could allocate set id 1 over an existing `S0001`. Fixed by moving the catalog to its own
`sets/catalog.bin[.tmp]`, ensuring it at boot before the legacy reconcile (adopt an intact pre-split index,
else rebuild from the validated Set folders with `nextSetId = max(folder id) + 1`), refusing a commit that
cannot establish the index, and giving the overlay a bounded list-refresh retry that keeps "read failed"
distinct from "read empty". Native: **3097 cases / 7 skipped / 3090 succeeded, all 114 suites PASSED**; build
`SUCCESS` at `ITCM 393,216 (code 392,216 + padding 1,000) ≥ 840`. **Device (fresh boot, this fix flashed):**
