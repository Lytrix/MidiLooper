## Identity, owners and commit boundary

- Production entry: `TrackManager::updateAllTracks` → `Track::playMidiEvents{,ForSlot}` → `Track::playCommittedLoopMidi` → MIDI sink and per-slot active-note ledger. `TrackManager` alone selects `activeLoopIndex`; an additional enabled slot remains independently sounding.
- Deferred source: live Capture/overdub on `Loop`, sealed Record range held by the Track stop job, selected complete `LoopSnapshot` or pinned retained source, or `EditManager` NOTE_EDIT delta. Only the source owner may mutate its content; a building whole-root Snapshot is never an interval playback authority.
- Window: `Track::stepPlaybackViewMaintenance` owns slot-qualified private `build`, complete immutable `ready`, published/served `current`, source pins and retirement. The existing main-loop deferred-owner enumeration grants the source and window owners' **needed** turns; the clock edge only reads/adopts/emits. All other admitted owners retain bounded non-starving opportunities.
- Commit boundary: first pin the native end-state oracle before changing selection policy; link and RED-prove the **new reader** behind the qualification gate while preserving all live legacy emitters. A correctly pinned qualification-only image MAY exercise that gated candidate after native/placement checks, so its device verdict can be obtained. Do not enable the default route or remove a fallback until its exact output/ledger, source-lifetime, active-resource and hardware continuity gates pass.
- Non-goals: no second publisher/queue/Manager, partial `LoopSnapshot` root, whole-take per recorded slot, stop/clock-edge sort, blanket Record/overdub priority, SD schema/interaction policy change, admission of unbounded same-tick density or attribution of a default-image gap to scheduling.

## New-path production oracle — outcomes, not legacy setup

E1/E2 below are **end-state behaviors**, not instructions to seed an old prepared pair, first-Record buffer, bridge or merged emitter. Input MIDI examples are independent accepted-content inventories; they do not prescribe how a new `current` is prepared. A case passes only if the actual production edge selects the Track-owned immutable window reader, with source/slot/generation/interval and physical storage identity, and disabling that reader turns the case RED. Legacy MIDI parity alone is a control, never acceptance. Build the initial `current` off-clock under the same Track window owner; a staged or empty old-route buffer is not a complete published reader view. Split E1/E2 into subcases where source availability or geometry differs instead of requiring every scenario to start in a particular legacy state.

**E1 — unchanged complete `current`.** For any sounding slot whose *new reader* holds complete source-qualified coverage of the traversed interval, neither wrap nor an unchanged source/revision requests a rebuild, acquires another view lease or relabels storage. The reader's physical `current`, cursor and per-slot ledger persist across every traversal for which that coverage remains valid; repeated calls at one edge emit nothing twice. Verify exact independent MIDI/ledger for a one-bar full-coverage example (channel 1 On pitch 48 velocity 100 at phase 0, Off@48; two traversals On@0/Off@48/On@768/Off@816), including the unchanged wrap with **zero new grants**. A qualifying long-loop interval can prove owner→reader selection and no work while its coverage lasts, but does **not** prove one-bar reuse across wrap. An additional enabled sounding slot on the same Track keeps its own view/cursor and MIDI trace across active-slot changes; a complete event-empty interval emits silence without blanket-closing a held note. Neither a whole-loop checkpoint nor a legacy whole-take representation is a prerequisite.

**E2 — accepted Record changes through the same reader.** Start Record with the new Track window owner and Capture adapter; any initially silent coverage must be a *complete new-reader `current`*, not the old empty first-bar reservation. Feed independent accepted MIDI (e.g. distinct NoteOn/Off pairs at phases 0/48 and late 700/740), recording Capture generation after each append. A build frozen before a relevant append cannot publish as its successor; the previously served view remains immutable. Control the **needed** source-owner and window-owner grants separately, complete a generation-qualified private successor, and adopt only at its qualified affected tick. On stop, if the serving complete `current` matches the frozen Capture generation, final loop geometry, covered content and closures, transfer its source hold to the job-owned frozen range **without changing the physical view, cursor or ledger**; on the next traversal compare independently expected On@768/Off@816/On@1468/Off@1508, never duplicate or early MIDI. If the final source, geometry or closure does not match, never relabel old content: retain only valid prior coverage, hold the frozen range until a corrected complete successor exists, and report waiting/late/fault against the earliest affected tick. Accepting a closure cannot depend on build success; a one-pass-late fallback is containment, not a passing deadline. A partial `LoopSnapshot` is not playback authority in either branch.

**E3 — private checkpoint and overlapping work.** Pause `Loop::stepPendingSnapshotPublish` with its whole-root candidate incomplete, while the qualified frozen Record range already answers E2's owed interval. Playback must continue through that range: withholding **only** these unneeded Snapshot turns leaves E2's source/window MIDI oracle GREEN and does not make the partial root an authority. Resume publication mid-bar without tearing `current`. A frozen source remains pinned while *any* current/ready/build view, reader, future-window request (including one not yet building), closure or uncancelled builder still needs it; release only after revision advance and the spec's single release predicate holds. Add a competing track/non-active sounding slot, persistence/display opportunity and an accepted overdub or NOTE_EDIT change between grains. Changing selected track/active slot invalidates only a candidate whose **own** slot/source/operation generation or clock epoch changed; an independently sounding unaffected slot keeps its reader and candidate.

**E4 — a genuinely needed source-owner turn.** Start with a retained pending Record interval whose frozen source qualification or range preparation is incomplete and for which no already-qualified Capture/retained source covers the requested interval. Withhold that *required* source-owner turn while granting playback-window opportunities: request stays waiting with its slot/generation/deadline named, no ready successor can be claimed and the edge does not read a partial candidate. Grant the exact source owner, then the existing window owner; a matching completed window may publish and reach the one reader with independently expected MIDI/ledger. This control turns RED when its required source grant is suppressed; it does not turn E3 RED by suppressing an unnecessary Snapshot turn.

**Discriminating RED controls:** suppress E4's **required** source-owner grant, E2/E4's required playback-window grant, the new reader, or the source-generation/physical-view guard separately. Each must fail its corresponding requested-window, exact MIDI/ledger, or stale-adoption assertion. Suppressing the unneeded Snapshot grant in E3 must stay GREEN. After a route cuts over, disabling its old emitter must leave that same oracle GREEN; a legacy-only green musical trace is baseline, not E1–E4 acceptance.
