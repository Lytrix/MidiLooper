Contract:
- Add a distinct terminal, non-recycled destructive-prefix generation per store. Accepted append (including out-of-order ticks and full-tail sealing) does not change it. Destructive mutators/ownership cuts invalidate it before row/directory writes, independently of legacy worker ownership generations.

Actual ID writes and nonempty static reference-release operations conservatively invalidate all new raw-prefix cursors through a pool-owned terminal alias generation. No per-chunk registry or extra payload storage. This is conservative restart, not mutation prohibition or frozen-range immutability enforcement; unrelated committed retirement can invalidate a live borrow and must be charged by future integration.
- Caller-owned forward cursor freezes an extent, retains chunk/row coordinates, and extends only after identity validation. One read call copies at most one row OR advances one chunk; no at() prefix scan, allocation, sorting, projection or refcount acquisition. Only successful explicit extension exposes a newer suffix; append cannot expand a frozen read implicitly.
- Each mutating deferred grain invalidates newly acquired cursors too. The worker's own legacy continuation remains valid because it uses the separate ownership generation. Bind/read/extend run serially on the existing main-thread owner.
- The caller MUST retain the physical store and prevent concurrent mutable workers while borrowing; discard the cursor before owner destruction/replacement. Cursor discard and local extent/progress access never dereference the owner. Store methods are the only validators; they compare cursor identity to their live receiver. No autonomous raw-pointer ready()/currency callback. No production borrower is installed by this slice, so no claim that existing Track guards retain a new borrower.
- Raw-prefix identity is NOT interval/phase/projection identity or current playback currency. Loop semantic receipts, Track cancellation/retention integration, live request/anchor/coalescing/adoption/stop and physical/input timing remain explicit later prerequisites. Current/ready view bytes and all target/default gates stay unchanged.
- Token exhaustion is zero terminal: existing cursors and all future bind/extend/read refuse, accepted content and legacy mutators continue unaffected. Pool lifetime separately refuses reset/recycled chunk IDs.
