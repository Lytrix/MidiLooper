## Evidence and authority

**VERIFIED route:** `MidiButtonActions::handleUndo` routes `TRACK_OVERDUBBING` to `TrackUndo::undoOverdubSession`, without global undo fallback. Its current Loop argument is obtained from the selected slot. `TrackManager::finalizeCaptureAndSelectSlot` can change `activeLoopIndex` while the previously active interval is still capturing, so the selected Loop can differ from the Loop that owns the overdub session. Redo has the analogous route.

**VERIFIED mutation:** live `Loop::undoOverdubSession` (session cursor zero) copies live `capture.store` to `overdubSessionLiveUndoEvents_`, clears that store, rebuilds the preview and increments capture/display generations. Live redo restores only that Loop store. `TrackUndo` then unconditionally invalidates the display frame. The capture records the first double at 107.360 s as live session undo and DISP falls 315→53 at 107.368 s. This is consistent with loss of the held Record display base; it does not prove Record content was deleted or identify the later Stop stall's first failing predicate.

**VERIFIED dual inventory:** accepted input is represented in Loop `capture.store` and `CaptureAdmissionStaging`; NoteOn also owns Track `pendingNotes`, reservations and reserved credits. NoteOff resolves identity from canonical capture and closes the matching reservation. The live Loop undo currently clears canonical rows without reconciling these Track-owned structures; redo reloads only Loop rows. A held NoteOff after that clear can fail identity/reservation matching and leave the Track pending note in place, blocking another same-pitch NoteOn. Overlap Hide/Shorten state is separately held by `Loop::pendingNoteChanges_`.

**VERIFIED isolation:** Stop admission exchanges the live staging role with a distinct free role, and moves held-note ownership into the stop job. The predecessor's frozen staging, raw extent, job pending notes and receipt are not the successor's live role. Track-wide `hasPendingDeferredOverdubStop()` is true for the exact supported overlap and must **not** be an undo refusal. Refusal may be based on this same interval already being owned by its own admitted Stop, not on a predecessor job or slot-only match. Existing live-only staging reset patterns do not constitute a complete undo/redo transaction.

**VERIFIED display:** `invalidateLiveDisplayCache(false)` clears the live frame and committed prefix. The existing held-gap draw-source path then has no frame authority to retain the Record base. `capturePreviewRevision`, sealed-preview keys and pending-change keys are separate overlay keys; the committed identity includes playback/root/window fields. A repair must retain only a qualified committed prefix and remove exactly the undone overlay. Do not assume a count alone proves source identity. Do not alter committed-wrap undo invalidation.

Authority reused: DEC-038 — overdub wrap commit and session undo (session-gated undo, no global-stack pop), DEC-068 — interval-owned overdub session, DEC-160 — predecessor-local finalization, DEC-161 — additive frozen staging roles. Extend Track/TrackUndo and existing DisplayManager APIs; no ownership transfer is proposed.

## Contract clauses

### C1 — Target identity

Resolve the Loop that actually owns this Track's open overdub session, not merely the currently selected slot. Verify the bounded search/uniqueness invariant against actual slot-switch code before editing. Zero or multiple matches, wrong Capture phase, or stale Track/slot/LoopId/interval identity is a named no-mutation outcome. Do not convert a selected-slot mismatch into an undo of another Loop.

### C2 — Predecessor and same-interval isolation

A different, still-finalizing Record/overdub predecessor does not block the live successor's undo/redo and is never mutated. Guard only against mutation of the exact interval already owned by its own Stop job (interval-qualified, not track-wide or slot-only), or against a live role demonstrably frozen by a job. Stale identity/generation refuses without mutation. Assert that predecessor raw extent, frozen role, job-owned pending notes, receipts and pass state remain unchanged in tests.

### C3 — Track-owned, failure-atomic operation

`TrackUndo` remains the undo owner and coordinates Loop plus Track-owned live input state. **Preflight must finish before the first mutation**: C1/C2 identities; session cursor/phase; runtime and live role availability; canonical-store and staging capacity/ownership; retained/open NoteIds and reservation capacity; redo payload/source/session identity as applicable; and all resources needed for a no-fail commit. If any precondition fails, preserve every row, reservation, credit, cursor, payload, frame and job state; emit a named refusal and do not consume the gesture.

The implementation may commit only through already-proven non-failing operations after preflight. A sequential mutation that can return/fail after Loop content has already changed is not failure-atomic. Prove any in-place selective rebuild has bounded work, pre-admitted capacity, and no allocating/failing tail; otherwise expose the needed existing-owner primitive/resource as an unresolved design issue before implementation.

Postconditions after a successful transition: Loop rows and the live staging inventory represent the same intended live interval; every retained Track pending note has its canonical On and matching reservation; closed/discarded identities are absent from both inventories; credits/open-note counts agree; pending overlap changes correspond only to retained musical decisions; the live generation cannot alias a prior admission. The predecessor/frozen/job-owned state is byte/identity unchanged.

### C4 — Sounding held-note policy (OWNER-RATIFIED H1)

**H1 ratified by the owner in this chat:** live undo removes closed live events and associated overlap deltas, but a NoteOn still sounding at the undo edge is not cut from beneath the performer. Retain its canonical On, staging row, Track pending entry, reservation and credits through the eventual physical NoteOff, which closes that same NoteId at the real release tick. It is not part of the undo payload and is not duplicated by redo. Further same-pitch input remains governed by normal pending-note policy until that NoteOff succeeds. No synthesized tick, blocked gesture or accepted-lifetime loss.

H2 (undo includes the open note and diverts its future closure into redo) is rejected for this contract because it requires a new accepted-input branch and exact future-Off payload ownership. Refusing undo while held or omitting the accepted lifetime is also rejected. Implementation and tests must establish H1 against the actual reservation/NoteOff owner before code is checked off.

### C5 — Redo identity and invalidation

Redo uses `overdubSessionLiveUndoEvents_` as the candidate payload only if fixtures prove it contains exactly the closed rows discarded by H1 while retained held-note pairs stay outside it. It is authoritative and qualified by the same open session, LoopId/slot and interval. Redo must preflight canonical/staging/reservation/credit capacity and payload identity before mutation; reconstruct exact accepted row order, ticks, channels, velocities, NoteIds and associated overlap state. Intervening accepted input must never be overwritten.

Any accepted ingress after undo, including a NoteOff that completes an H1-retained held note, invalidates the redo branch through its existing owner hook (or a precisely specified equivalent) before admission mutates the live inventory. Counts alone are not identity proof. Session close, interval/slot replacement, source supersession and Stop/publication also invalidate redo via their owners. Failed redo preserves the payload and undone state. Test further ingress and held NoteOff after undo, assert exact invalidation, and prove no stale replay can occur.

### C6 — Display committed-base continuity

On the live-only undo/redo branch, retain the prior committed prefix only if its Track/slot, window, playback revision and published-root identity are still qualified for the current frame. Truncate only the live overlay suffix and clear/rebuild overlay keys; preserve the committed count and compose metadata needed by the existing handoff. If source identity is not qualified, use the existing safe full-rebuild path. Redo restores only the live overlay. A wrap/committed-pass undo with `playbackRevision` change retains today's full invalidation behavior. Do not remove `captureDisplayRevision` from the committed key without a separate fixture proving the narrower overlay-only handling insufficient and a display-wide regression check.
