## Oracle fixed before behavior edits

- Acceptance on a multi-chunk raw committed fixture leaves all IDs/counters/pool/reference counts unchanged; repeated queries and withheld turns cannot advance work.
- One chunk grant assigns exactly the first chunk; later chunks remain untouched. Next grant advances only the pass or next chunk, never drains the source. Completion is unavailable until explicit terminal grant. Explicit IDs start at 400 and preserve a preexisting 9000 ID, Off and controller rows.
- Record, empty/disabled overdub and active overdub fixtures preserve legacy pass/row assignment ordering. Compare independently pinned IDs and synchronous legacy output on a separately owned source.
- Reset/source replacement, changed revision, wrong receiver and changed Capture source reject before touching later chunks; fresh begin resumes idempotently. A completed result becomes stale on canonical-generation change; query does not mutate it.
- Invalid committed reference faults without minting an ID. Empty Loop completes on explicit transitions; discard/rebegin is metadata-only. Shared chunk borrowers preserve reference counts and exact MIDI payloads.

Harness: existing real Loop/LoopEventStore entry suite; synthetic restored committed input is cold fixture construction via real store chunk sealing/ref transfer (bypasses Record normalization that normally assigns IDs). No domain stub decides worker outcomes. Fixed drain limit derived from pass/chunk count, no sleeps. New API prelink missing symbols is not behavioral RED; post-link stepping and stale-receipt mutations must fail independent assertions and restore byte-identically.
