# Task 4.6 — the execution grain (`stepTilePreparation`)

**Date:** 2026-10-29
**Change:** `realtime-idle-owner-admission-bound`
**Status:** grain primitive implemented and parity-verified. **Not yet wired to an owner turn.**

## What landed

`LoopContentResolution::stepTilePreparation(passes, loopLength, windowStart, windowLength, eventBudget, TilePrepCursor&)`
— the **same** derivation `resolveDisplayNotesInWindow` performs, stepped over a declared **event budget**
one pass at a time:

- ordered pass list: record first, then active overdubs by `mergeSequence` (the same order the
  single-shot resolve uses — that is what makes parity possible);
- each pass is traversed with the existing resumable `CommittedEventRange::appendWindowBudgeted`, so the
  cursor survives across turns;
- a pass's edit rows and per-pass local pairing run **only when that pass's window traversal completes**;
- nothing is published until every pass is complete (`cursor.complete`).

The tile remains the **correctness/publication** unit; the budget is the **execution** unit. A tile can
now need several turns without ever exposing partial content.

Envelope: up to `kTilePrepMaxPasses = 32` passes; above that the caller takes the single-shot path as a
named fallback.

## Parity evidence (the point of the exercise)

`RIAO-2.R` — the grain-stepped result must equal the single-shot windowed result at **every** budget, on
the 8-bar window of the 8-bar fixture:

| budget (events/turn) | turns | notes | equal to single-shot |
|---|---|---|---|
| 1 | 16 | 8 | yes |
| 3 | 6 | 8 | yes |
| 7 | 3 | 8 | yes |
| 64 | 1 | 8 | yes |
| 100000 | 1 | 8 | yes |

`RIAO-2.S` — the **dense-tile RED** required by 4.6: a 4-bar tile of a 31-bar/310-note pass at the
declared 64-event grain needs **2 turns**, reports incomplete on the first, and its completed result
equals the single-shot windowed derive for the same window (40 notes, same ids and geometry). A
tile-sized (unbounded) turn would have returned in one call — the test asserts `turns > 1`.
