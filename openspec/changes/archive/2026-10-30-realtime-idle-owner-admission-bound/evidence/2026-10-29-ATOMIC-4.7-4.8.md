**Date:** 2026-10-29
**Change:** `realtime-idle-owner-admission-bound`

## The circularity

Each remaining step is individually justified, but they depend on each other in a cycle:

| step | needs |
|---|---|
| **retire the moving-window producer** (4.8) | the view to be cut from tiles the worker has published content for |
| **worker publishes tile content** | the span cache to have exactly one producer — i.e. the moving-window producer retired |
| **view reuse becomes per-tile** | prepared tiles to carry content, and the prerequisites to defer when they do not |
| **prerequisites wired** | a deferral to be dischargeable, which requires tiles to actually complete |

Removing any one edge in isolation breaks content:

- remove the producer first → the cache has no content for tiles the worker never wrote, so every view
  refresh is a no-op and the view never advances (silently: the coverage rule keeps the old view, which is
  correct only while it still covers the required interval);
- publish from the worker first → two producers of a single-owner cache, which is what
  `test_predecessor_publication_mid_scan_discards_the_private_prefix` caught
  (`evidence/2026-10-29-WORKER-OWNERSHIP-FINDING.md`);
- wire the prerequisites first → decisions defer into a hole nothing discharges.

So this is the same atomicity rule the design already applies to the source-view child (D3): the
interdiction and the bounded replacement land together. The slice below is that unit.

## The one shape that removes the circularity

**One producer (the worker function), two drivers.**

1. `rebuildOverdubSourceSpanCache` stops being called from the maintenance paths
   (`rebuildOverdubSourceView`'s idle/wrap refresh and `mergeOverdubSourceViewForHoldContext`). Those become
   **read-only cuts** of the cache.
2. The worker becomes the only writer: on the grain that completes a tile it publishes the tile's content
   **and** its prepared bit in one step, so "prepared" and "has content" cannot diverge.
3. **Session open stays synchronous but goes through the same worker**: mark the tiles of the open window
   required, then drive `serviceOverdubCoverageTurn` under the open path's existing budget until the window
   is prepared or the budget is exhausted. One producer, two drivers — no second writer, no second contract.
4. The view's reuse predicate becomes **per-tile**: the window is servable when every tile it covers is
   prepared for the current generation. Otherwise the view is not refreshed, and the prerequisite that
   needed it defers by name.
5. `kOverdubSourceWindowBars` and the playhead-centred window stop being correctness mechanisms; the open
   window and the tile set are the only selectors left.

## Execution packet (slice `RIAO-3`)

- **Owner:** `Loop` (span cache + coverage), driven from `Track::processDeferredIdleMaintenance`
  (deferred) and from `Loop::rebuildOverdubSourceView("open")` (synchronous, bounded).
- **Preconditions:** coverage session active; no private-predecessor scan pending (the worker already
  yields); the open path holds its existing 50 ms gate.
- **Postconditions:** the cache has exactly one writer; every cached note belongs to a prepared tile;
  a view refresh either serves a fully prepared window or does not happen.
- **Invariants:** C3.1/C3.2/C3.5 (scan ownership, no partial prefix mixed with a committed suffix,
  `fullLoop`-style completeness now per tile); identity composition across tiles; the coverage rule.
- **Failure behaviour:** an unprepared window is a named deferral, never a partial serve. A scan taking
  ownership makes the worker yield and stays owed.
- **Non-goals:** no change to overlap evaluation, the delta grammar, or the open path's budget.
- **Oracle:** the existing suites plus the convergence fixture; the device oracle unchanged.

### REDs to write before the change

1. **Single producer:** with the maintenance derive removed, a view refresh over a window whose tiles are
   not all prepared performs **no** cache write and reports owed; once they are prepared it serves.
2. **Content/bit atomicity:** after any turn, every note in the cache lies in a tile whose prepared bit is
   set (the assertion that failed when the worker published early — now it must hold for the sole producer).
3. **Open window prepared through the worker:** a session opens, the open path drives the worker, and the
   first overlap decision for a note inside the open window is **ready** (no deferral).
4. **Prerequisite deferral discharges:** a note whose window was unprepared defers at finalization and
   completes with the same delta once the tile is prepared, exactly once.
5. **Scan ownership respected:** a private-predecessor scan in progress leaves the cache untouched and the
   tile still owed; on completion the worker resumes.
6. **Convergence:** touch every tile, prepare all, and the candidate set equals the whole-loop derivation.

### Ordered steps

1. REDs 1–2 (single producer, atomicity) against the current tree — expected red.
2. Make the worker the sole writer (publish content + bit on completion); remove the maintenance derive.
3. Session-open driver (step 3 above) + RED 3.
4. Per-tile reuse predicate in the view cut + RED 4.
5. Scan-ownership RED 5 and the convergence fixture 6.
6. Retire `kOverdubSourceWindowBars`; update `ExecutionBounds.md` and the overlap guide in the same commit.

## Why not start it now

Steps 2–4 are a single edit to the same three functions with no intermediate buildable state: making the
worker the sole writer while the view still cuts by a moving window leaves the view unrefreshable, and
removing the window while the cache is unpopulated leaves it unservable. Splitting it would put a
half-consistent overlap source on the board, whose failure mode is a corrupted take rather than a slow
frame — the one outcome this change exists to avoid.

The tree is green and consistent at the current point; the atomic slice above is the next unit of work.
