# C1 — import committed `Loop::passes` into a disposable manifest (host-verified)

Date: 2026-11-01. Scope: DEC-246 (Stage C, one read path, writes stay with today's firmware). No firmware call site
yet, no device change. Code: `include/RevisionStore/RevisionImport.h` (`RevisionStore::importLoop`). Suite:
`test/test_revision_store_differential`.

## What the import does

`importLoop(loop, store)` replaces the store's content with the loop's committed, active state:

1. **Capture runs**, one per active capture pass in commit order (Record, then overdubs by `mergeSequence`), each
   holding that pass's committed chunk rows (DEC-245 layer 1). NoteOff rows are stamped with their note's id using
   production's own pairing (`NoteUtils::reconstructDisplayNotes`), so hides and zero-length suppression see both
   ends of a note.
2. **One Edit run** for all active Note edit passes: per edited target, a hide plus its final geometry after
   production's own `applyNoteEditPass` of that target's edit rows, in edit-pass id order. Edit semantics are not
   re-implemented. (One run rather than one per edit keeps the manifest within its run budget.) **This collapsed Edit
   run is a Stage-C shadow-import convenience, valid for parity only.** It is built from production's *final* apply
   result, so it discards edit provenance and order. It is not a candidate long-term representation: when the store
   owns edits (stage D/E), each edit is its own immutable run (DEC-245).
3. **Named refusals, no partial mirror:**
   - `DeniedCapacity`: the slot does not fit the store;
   - `UnsupportedEditPass`: an active ControlChange or Audio edit pass;
   - `NoRecordPass`: nothing committed and active.

   On refusal the store is left empty and the production reader stays authoritative.

The import is off-line / stopped work: it walks every committed row and uses production vectors. It is never a
real-time path. A bounded or stepwise import is a C3 concern.

## Parity

After every production state in the differential suite, the loop is imported into a separate store sized inside the
Stage-C cap (512 pages × 512 B = 256 KiB). The edit index is built off the edge (`stepEditIndex(256)`), and the
manifest is read the real-time way: `productionCompat()` with `HideLookup::IndexOnly`. The result must equal
production's effective view (`tryCopyCurrentSnapshotEditViewEvents`) group for group, (tick, class) with exact
multisets.

| Scenario family | States compared |
|---|---|
| B.2a hand cases (same-tick classes, wrap, sustain, cross-pass overlap, zero-length) | all |
| B.2b seeded (40 × 12, undo/redo, branch-after-undo) | 520 revisions |
| B.3 hand cases (Hide, Shorten incl. wrap and channel 3, NOTE_EDIT pitch/length/velocity/delete, undo of each) | all |
| B.3 seeded (overdubs with Hide/Shorten, NOTE_EDITs, undo) | 132 revisions |
| **Total import-parity checks** | **659, all equal**; 0 NoteOffs left unpaired |

Refusals (`test_import_refusals_are_named_and_leave_no_partial_mirror`): a 120-row take into a 96-row pool gives
`DeniedCapacity` with 0 pages owned and no current manifest. An active ControlChange edit pass gives
`UnsupportedEditPass`, refused before anything is written.

## Finding fixed on the way

Production's cross-pass identical-event collapse applies **between capture passes only**. A ch2 pitch-95 NoteOff
produced by a NOTE_EDIT and an overdub's own ch2 pitch-95 NoteOff on the same tick are both kept by production. The
import puts the edit run after all capture runs, which exposed that the store's `productionCompat()` collapse also
compared against edit replacement rows. It now skips Edit runs on both sides (a compacted run counts as capture).
Before the fix, the run stopped at the first divergence (B.3 seed 1, step 7) after 545 checks; with it, all 659 pass.
